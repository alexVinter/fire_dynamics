# Как сделать Pull Request — по шагам

**Pull Request (PR)** — это запрос «вот мои изменения, добавьте их в общий проект». Заказчик смотрит код в PR и принимает его (или просит доработать).

Ниже — что сделать **на своём компьютере**, потом **на сайте GitHub**.

---

## ЧАСТЬ 1. На своём компьютере

Открой папку проекта и открой терминал (PowerShell или cmd) **в этой же папке** (там, где лежит `docker-compose.yml`).

### Шаг 1. Обновить главную ветку

Введи по очереди (после каждой строки — Enter):

```
git fetch origin
git checkout main
git pull origin main
```

Так у тебя будет свежая версия «главной» ветки.

---

### Шаг 2. Создать свою ветку

Одна команда (имя ветки можно заменить на своё, например `module-1`):

```
git checkout -b module-1-init-and-db
```

Теперь ты работаешь в отдельной ветке, а не в `main`.

---

### Шаг 3. Сохранить изменения в Git (сделать коммит)

Если ты уже что-то менял в файлах:

```
git add .
git status
```

`git status` покажет, какие файлы попадут в коммит. Потом:

```
git commit -m "Модуль 1: проект, модели, админка, тесты"
```

В кавычках — короткое описание: что сделано. Кавычки должны быть именно такие `"..."`.

---

### Шаг 4. Отправить ветку на GitHub

Подставь **то же имя ветки**, что в шаге 2:

```
git push -u origin module-1-init-and-db
```

Если GitHub попросит логин и пароль — введи. После этого твоя ветка появится на GitHub.

---

## ЧАСТЬ 2. На сайте GitHub

### Шаг 5. Открыть репозиторий в браузере

Зайди на страницу своего репозитория, например:  
`https://github.com/ТВОЙ_ЛОГИН/НАЗВАНИЕ_РЕПОЗИТОРИЯ`

---

### Шаг 6. Нажать «Compare & pull request»

Сразу после того как ты сделал `git push`, на GitHub часто появляется **жёлтая полоска** с кнопкой **«Compare & pull request»**. Нажми её.

Если полоски нет — перейди во вкладку **Pull requests** (сверху) и нажми зелёную кнопку **New pull request**.

---

### Шаг 7. Убедиться, что ветки выбраны правильно

Сверху будут два выпадающих списка:

- **base:** должна быть ветка **main** (или та, куда нужно влить код).
- **compare:** должна быть **твоя** ветка (например, `module-1-init-and-db`).

Ниже покажется список изменённых файлов — проверь, что там только то, что ты менял.

---

### Шаг 8. Заполнить заголовок и описание

- **Заголовок (Title):** одна строка, например:  
  `Модуль 1: инициализация, БД справочников, админка`

- **Описание (Description):** можно написать в свободной форме, например:  
  «Сделан Модуль 1: Docker (backend, frontend, БД), модели core, админка, линтеры, тесты. Как проверить — в файле RELEASE_NOTES.md.»

Можно просто скопировать текст из RELEASE_NOTES.md в описание — так заказчику будет понятно, что сделано и как проверить.

---

### Шаг 9. Создать PR

Нажми зелёную кнопку **Create pull request**.

Готово. Запрос на добавление кода создан. Дальше заказчик смотрит PR и либо принимает его (Merge), либо пишет замечания — тогда ты правишь код в той же ветке, снова делаешь `git add`, `git commit`, `git push`, и PR обновится сам.

---

## Кратко: что ты делаешь

| Где        | Что делаешь |
|-----------|-------------|
| Компьютер | Обновил main → создал ветку → закоммитил изменения → отправил ветку на GitHub (`git push`) |
| GitHub    | Открыл репозиторий → нажал «Compare & pull request» (или New pull request) → выбрал base = main, compare = твоя ветка → написал заголовок и описание → нажал Create pull request |

После этого пакет считается поданным через Pull Request и готов к проверке заказчиком.
